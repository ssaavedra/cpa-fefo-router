# Design: quota in API-equivalent dollars

Status: in progress on branch `usd-accounting`.

## Problem

The router measures client demand and account size in "plan-weeks", splitting each
hour's weekly-utilization delta between clients by raw token count, and sizing
accounts with a hand-set relative `capacity`. Raw tokens are dominated by cache
reads, which cost 1/20 of uncached input on Claude Opus. Measured on the
production hub (2026-11-24) raw tokens put a Team Premium seat at ~3x Pro;
priced at API rates it is 5.5x, matching Anthropic's published multiplier.

## Unit

Every quota quantity is **API-equivalent US dollars** ("$"), computed per request
from the model's public API price:

    usd = uncached_input × in + output × out + cache_read × cr + cache_write × cw   (per 1M tokens)

- account capacity     = $ one full weekly window holds (learned, see below)
- remaining            = weekly remaining share × capacity
- client demand        = $ per hour (max of 24h and 7d averages, as today)
- expected / spare     = $
- `min_spare`          = share of the account's capacity (unchanged meaning: 0.03 = 3 % of a week)

Raw tokens stay recorded for display only.

## Components

### 1. `internal/pricing` (new package)

- `Price{Input, Output, CacheRead, CacheWrite float64; Tiers []Tier}`, per 1M tokens.
  `Tier{AboveContext int64; Price}` from models.dev `cost.tiers` (`tier.type == "context"`).
- `Usage{Uncached, Output, CacheRead, CacheWrite int64}`; `NormalizeUsage(provider, pluginapi.UsageDetail) Usage`
  mirroring CPA's normalisation (`sdk/cliproxy/usage/accounting.go`): Claude reports cache
  tokens separately from input; OpenAI/Codex `InputTokens` includes `CachedTokens`.
  Reasoning tokens bill as output.
- `Table` = map of model id → Price plus metadata (source, synced_at).
  `Resolve(model) (Price, Match)` tries: exact id; id with trailing `-YYYYMMDD` stripped;
  id with known suffixes stripped (`-thinking`, `(...)`, `[1m]`); longest table key that is a
  prefix of the id. `Match` records which rule hit, or `Unknown`.
- **Unknown model price is protective, never zero.** It is the per-component maximum over
  all known models of the same provider family (`claude-*` / `gpt-*`, `o*`, `codex-*`).
  Over-pricing makes the account's home demand look larger, so less is lent away and the
  account's own clients keep their quota. Status shows a warning listing unknown models.
  Usage priced this way is excluded from capacity learning (it would inflate capacity).
- Sources, highest wins: config `prices:` overrides → last models.dev sync (persisted in the
  state file) → embedded snapshot (`go:embed`, generated by `scripts/update-prices.sh`,
  trimmed to the `anthropic` and `openai` providers).
- `ParseModelsDev([]byte) (Table, error)`: reads `<provider>.models.<id>.cost`.

### 2. Claude usage report (`internal/quota`)

Response headers carry only the shared 5h and 7d windows. The Fable sub-limit and the
extra-usage setting are only in `GET https://api.anthropic.com/api/oauth/usage`
(headers `Authorization: Bearer <access_token>`, `anthropic-beta: oauth-2025-04-20`).

`ParseClaudeUsage([]byte, observedAt) (UsageReport, error)` where `UsageReport` holds:

- shared windows from `limits[]`: `kind=session` → "5h", `kind=weekly_all` → "7d"
  (`percent` 0..100, `resets_at` RFC3339, missing/null → no window);
- scoped windows: `kind=weekly_scoped` with `scope.model.display_name` → window named
  `7d:<lower model family>` e.g. `7d:fable`, `Remaining = 1 − percent/100` (percent is of
  the sub-allowance), plus `Allowance` from `weekly_scoped_shares[].allowance_percent_of_weekly/100`
  matched by `limit_index` (index into `limits`), default 1;
- `ExtraUsageEnabled` from `extra_usage.is_enabled`, `SpendLimitReached` from
  `extra_usage.spend_limit_reached`.

A model family with no scoped window on an account that reports a usage report means the
plan has no included allowance for it (Pro + Fable runs on paid credits only).

The router polls this for each Claude account every `usage_poll_interval` (default 5m)
through host callbacks: `host.auth.get` (credential JSON → `access_token`) and
`host.http.do` (goes through CPA's proxy). Never log or persist the token. On 401/403,
back off to the next interval.

### 3. Router

- `hourBucket` gains `USD map[string]float64` and `Unpriced bool`. `split()` divides an
  hour's weekly delta by $ share (fallback tokens, then requests, as now).
- **Capacity learning per account, per weekly cycle.** State `capacityLearn{CycleReset,
  USD, Delta, Estimate, Previous, Tainted}`. Each usage record with a weekly reading adds its
  $ and CPA-attributed delta (external usage excluded) to the current cycle. When the weekly
  `ResetAt` moves to a new cycle, the finished cycle's estimate becomes `Previous` and the
  cycle restarts: capacity is re-learned every weekly renewal, so plan upgrades and
  downgrades show up within one week. `Estimate = USD / Delta` once `Delta ≥ learn_min_delta`
  (default 0.05). Unknown-priced usage marks the hour tainted and is excluded.
  Effective capacity: current estimate → previous estimate → config prior.
- Config prior: `capacity` (relative, Pro = 1) × $ per unit, where $ per unit is the median
  learned $/unit over accounts that have an estimate, else `default_unit_usd` (default 220,
  measured Pro week on the hub). Config may also give `capacity_usd` per account to pin it.
- **Scoped (Fable) gating.** For a request whose model family has a scoped window on the
  account, the account is excluded when that window's estimated remaining < `min_remaining`.
  Estimated remaining = last polled remaining − ($ spent on that family since the poll ÷
  (allowance × capacity)) — pro-rata from cost between polls. An account whose usage
  report shows no allowance for the family is excluded for that family when extra usage is
  enabled or unknown (it would bill credits). Exclusion applies to pinned sessions too.
  Scoped exhaustion never blocks other models on the account.
- Fable demand and spare are tracked per scoped window the same way as weekly, so Fable
  requests prefer the account whose Fable allowance expires first.
- Pricing sync: refresher fetches models.dev daily (`pricing.sync_interval`, default 24h;
  `pricing.url`), persists the table in the state file. Failure keeps the last table.

### 4. Display units

- Status JSON carries both $ and tokens. `GET .../status?units=usd|tokens` and the UI toggle
  choose which the text/UI shows; config `display_units` sets the default (`usd`).
- Metrics: `fefo_cost_usd_total{client,account}` next to `fefo_tokens_total`; account gauges
  in $ (`fefo_account_capacity_usd`, `_remaining_usd`, `_expected_usd`, `_spare_usd`,
  `fefo_account_scoped_remaining{window}`), `fefo_client_demand_per_hour{unit="usd"|"tokens"}`,
  `fefo_unknown_model_requests_total{model}`, `fefo_prices_synced_timestamp`.

## Out of scope

Codex scoped limits; reading Anthropic's dollar limits (`limit_dollars` is null today).
